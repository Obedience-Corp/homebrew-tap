# Obey Voice desktop cask

The CLI formula and macOS desktop cask share this tap but install separate
packages. `Casks/obey-voice-app.rb` is generated by the engine release coordinator
only after a Developer ID signed, notarized, and stapled desktop archive is
publicly downloadable with its verified SHA-256. Do not add a placeholder
cask or an ad-hoc signed app as a public release.

The owning engine command is `just release create vX.Y.Z`. Its enabled
`homebrew_cask` adapter applies starting with v0.3.1. The engine owns signing
credentials, source/version checks, asset publication, and cask generation.
This tap's `packaging/obey-voice-cask.json` contract declares the verification
workflow used before and after merging the generated cask PR.

`obey-voice-cask.yml` runs on disposable macOS 15 Apple Silicon runners. It
audits the exact tap revision, installs to a temporary Applications directory,
checks bundle identity and source provenance against the public tag, verifies
Developer ID/hardened-runtime signatures, the stapled ticket and Gatekeeper
acceptance, and starts the bundled engine with disposable configuration. When
main contains an older cask, it tests upgrading from that version. Every run
tests reinstall and uninstall and preserves fixture settings/model data.
The first release records no prior-version upgrade rather than claiming one.

The coordinator publishes and verifies public download bytes before creating
the cask PR. It waits for this workflow, honors review/merge protection, and
then dispatches `public` mode against merged main. Verification support can
merge before the first cask exists, but a release dispatch without the cask
fails. Support-only PR runs explicitly report that installation was not tested.

The app is installed with:

```sh
brew install --cask obedience-corp/tap/obey-voice-app
```

That command is usable only after the first cask release is published. The app
contains its own engine/native libraries and leaves the CLI formula independent.
Neither normal uninstall nor upgrade removes settings, sessions, personas or
model caches. No `zap` deletion of shared user data is configured.
